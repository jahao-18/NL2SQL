# MVP 演示数据设计

本文件定义后续种子数据的业务含义。阶段 1 修改 `scripts/seed_teaching_db.py` 时，应按本文档生成确定性账号、课程、提交、通知和学习支持事项。

## 1. 数据设计原则

- 演示数据必须有因果关系，不能只依赖随机分数和随机状态。
- 每个角色至少有一个“能做事”的账号，也要有一个“越权会失败”的对照账号。
- 同一条演示链路必须覆盖发布、提交、退回、补交、评分、发布成绩、学习支持待办。
- 支持事项只基于明确事实生成，例如连续未交、累计迟交、连续缺勤。

## 8. 阶段 1 种子数据落地要求

- 账号、课程、作业、提交、支持事项均使用固定编码，便于测试引用。
- 种子脚本重复执行后数据保持一致，不产生重复账号或重复事项。
- 随机历史数据可以继续存在，但演示链路数据必须可稳定定位。
- 每条支持事项必须能追溯到作业或考勤事实，不允许只写结论。
