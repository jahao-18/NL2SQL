# V3-0.3 增量迁移基础完成报告

> 完成日期：2026-07-18
> 阶段状态：已完成
> 下一任务：V3-1.1 页面上下文与权限复核

## 1. 本阶段交付

项目已经建立 V3 专用的增量迁移执行器：

- `app/core/v3_migrations.py` 定义不可变的有序迁移清单。
- `v3_schema_migration` 保存版本、唯一迁移名、说明、SHA-256 校验值、执行耗时和时间字段。
- SQLite `PRAGMA user_version` 保存当前 V3 schema version，首版为 `3001`。
- 应用原有 `ensure_mvp_schema()` 完成旧结构维护后，自动执行待处理的 V3 迁移。
- 同一批待执行迁移及账本初始化处于一个 `BEGIN IMMEDIATE` 事务中，任一 SQL 失败都会整体回滚。
- 已应用迁移如果发生版本、名称或校验值漂移，启动会明确失败，不会静默覆盖历史。
- 原有 `schema_migration` 和 B.6 一次性身份岗位迁移语义保持不变。

首个迁移 `v3_0001_migration_foundation` 只建立迁移基础设施和账本索引，不提前创建 V3-1 的助手业务表。

## 2. 后续迁移开发规则

V3 后续新增表、列、索引或数据修复时：

1. 在 `V3_MIGRATIONS` 末尾增加更高且唯一的版本，不修改已经应用的历史迁移。
2. 一个 `statements` 元素只能包含一条可由 `sqlite3.Connection.execute()` 执行的 SQL，不使用会隐式提交的 `executescript()`。
3. 新表必须设计业务唯一约束、查询索引、`created_at`、`updated_at` 和必要外键；没有适用外键时应在设计说明中明确原因。
4. 数据回填和结构变更放在同一个迁移事务中；失败后由执行器统一回滚。
5. 测试继续复制教学库到 pytest 临时目录，不直接修改仓库中的 `data/teaching.db`。
