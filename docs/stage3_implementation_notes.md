# 阶段 3：学习支持待办与辅导员闭环实现说明

## 1. 阶段目标

阶段 3 将“学业预警”从教师数据看板中拆出，建设面向辅导员和学生本人的学习支持流程。系统只根据可解释教学事实创建待确认事项，不生成正式学业警告、处分结论或不可解释风险分。

## 2. 已实现业务流程

### 2.1 透明规则检查

首版规则固定为三条：

| 规则 | 触发口径 | 事实依据 |
| --- | --- | --- |
| 连续两次未提交 | 同一开课班中相邻两份已截止作业均无有效提交 | 课程、作业名称和截止时间 |
| 累计两次迟交 | 同一开课班中迟交记录累计达到两次 | 课程和迟交作业名称 |
| 连续两次缺勤 | 同一开课班中相邻两次课均为缺勤 | 课程、课次和考勤日期 |

尚未截止的作业不会计为未提交。规则命中后只创建 `open` 状态的待确认事项；相同学生、相同规则已有未关闭事项时不会重复创建。

### 2.2 路由与数据范围

- 根据学生行政班和 `counselor_class_group` 带班关系路由给责任辅导员。
- 没有带班关系的规则事件写入 `support_unassigned_case`，不广播给全部辅导员。
- 辅导员只能查询和处理本人所带行政班学生。
- 教师、非范围辅导员和其他学生访问事项均返回 `403`。

### 2.3 辅导员处理闭环

状态流转严格遵循：

`open -> contacted -> tracking -> improved -> closed`

其中：

- 首次联系必须填写联系方式和处理记录。
- 进入跟进中必须填写复查时间。
- 标记已改善必须记录后续事实。
- 关闭必须填写原因，关闭后历史记录不删除。
- 每次流转记录操作者、时间、联系方式、学生反馈、复查时间和前后状态。
- 辅导员可选择是否把支持建议同步给学生；内部谈话记录不会直接展示给学生。

### 2.4 学生主动沟通

学生可以提交预约沟通或问题咨询，填写问题和希望沟通时间。请求根据行政班路由给辅导员，辅导员可受理、完成或拒绝并填写回复。学生只能查看本人的请求和回复。

## 3. 页面结构

### 辅导员端

- 登录后默认进入“学习支持待办”。
- 顶部显示待确认、跟进中、待复查和新沟通请求数量。
- 左侧按状态筛选事项，右侧展示事实依据、建议动作、处理时间线和状态操作表单。
- 下方集中处理学生主动发起的预约与咨询。

### 学生端

- “学习支持”作为独立菜单，不与课程作业或教师批阅混合。
- 只展示辅导员明确共享给本人的支持建议、建议行动和复查时间。
- 不展示辅导员内部记录、其他学生事项或正式“风险分”。
- 可发起沟通并查看受理状态和辅导员回复。

## 4. 新增接口

| 方法 | 路径 | 角色 | 用途 |
| --- | --- | --- | --- |
| GET | `/api/teaching/support/cases` | 辅导员、学生 | 辅导员查看本人范围；学生查看本人已共享事项 |
| POST | `/api/teaching/support/cases/refresh` | 辅导员 | 检查本人带班范围内的三条透明规则 |
| GET | `/api/teaching/support/cases/{id}` | 辅导员、对应学生 | 辅导员获取内部时间线；学生仅获取共享内容 |
| POST | `/api/teaching/support/cases/{id}/transition` | 辅导员 | 联系、跟进、改善或关闭事项 |
| GET | `/api/teaching/support/requests` | 辅导员、学生 | 查询本人范围内的沟通请求 |
| POST | `/api/teaching/support/requests` | 学生 | 发起预约或咨询 |
| PATCH | `/api/teaching/support/requests/{id}` | 辅导员 | 受理、完成或拒绝请求 |

## 5. 数据结构

- `support_case`：支持事项、规则、事实依据、状态、复查时间、学生可见性和建议动作。
- `support_case_log`：每次联系与状态变化的不可删除记录。
- `support_request`：学生主动预约或咨询及辅导员回复。
- `support_unassigned_case`：无带班关系时的管理员待分配队列。
- `audit_log`：规则命中、状态变化、请求创建和回复操作审计。
- `notification`：共享建议、学生请求和辅导员回复的站内通知数据。

## 7. 当前限制

1. 规则检查目前由辅导员在页面手动触发；正式部署应改为后台定时任务，同时保留人工重跑入口。
2. `support_unassigned_case` 已保存无负责人事件，但管理员分配页面尚未实现。
3. 站内通知已写入数据库，统一通知中心仍属于后续迭代。
4. 当前不接入短信、微信、邮件，也不保存电话录音或聊天正文附件。
5. “已改善”由辅导员引用后续事实确认，系统不会仅凭一次提交自动关闭事项。
