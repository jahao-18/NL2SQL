# 智能问数功能与安全审计记录

## 审计范围

本次检查覆盖智能问数 API、数据源选择、Schema 权限裁剪、提示词输入、多轮历史、SQL 生成/回修、表与字段白名单、行级范围、只读执行、超时/行数限制、课程分析问数、前端启动隔离和角色权限。

## 已确认正常

- 问数主链路仍按“结构加载 → 可选检索 → SQL 生成 → 安全校验 → 只读执行 → 结果格式化”工作。
- LLM、检索和执行失败会返回结构化错误，不会终止 FastAPI 进程。
- SQLite 使用只读 URI，PostgreSQL 配置只读事务，并设置查询超时和最大结果行数。
- 学生、教师、辅导员、学院的真实模型调用均生成了正确范围条件并成功执行：`student_id`、`teacher_id`、`counselor_id`、`college_id`。
- 课程分析继续只使用课程级派生分析表，并同时限制 `teaching_class_id` 与本人身份范围。

## 本次发现并修复

1. 行范围条件此前只做全文正则搜索，可被 `OR 1=1`、注释、字符串、无关子查询、`UNION`、`NOT` 或布尔反转伪造。现改为逐查询块检查，范围等式必须是独立的顶层 `AND` 条件；范围查询保守禁止 `OR` 和集合查询。
2. 教师的成绩/选课事实表、学院汇总表以及辅导员行政班此前存在范围规则覆盖不足。现补齐教师课程链、学院汇总 `college_id`、辅导员 `counselor_class_group.counselor_id` 和支持事项负责人规则。
3. 敏感字段检查此前只看最外层查询，可通过 CTE/子查询、未限定字段名或带引号标识符带出。现对每个查询块检查，包括 `name`、`id` 和带引号字段。
4. 空表权限此前会被 Schema 过滤器误解释为全部表。现空权限严格得到零表，并在 API 层拒绝没有 `ask` 功能的工作身份。
5. 非管理员此前能看到和选择外部评测数据源，角色表权限可能与同名外部表发生混淆。现普通教学角色只可查询 `teaching`；管理员保留外部只读数据源能力。
6. 新增危险读取/延时/文件输出拦截，包括 SQLite/PostgreSQL/MySQL 常见文件函数、`SLEEP`、`BENCHMARK` 和 `INTO OUTFILE/DUMPFILE`。
7. 问数历史、数据源名和用户术语条目新增请求大小上限，降低超大请求和提示词滥用风险。
8. 无问数权限的个人中心角色不再启动时请求数据源，也不会被初始化逻辑导向智能问数页面。
9. `evaluation.student_id` 已加入教师不可输出的学生身份字段集合。

## 验证方式

- 自动化攻击用例覆盖注释、字符串、嵌套查询、CTE、集合查询、范围条件反转、敏感字段别名、危险函数、跨数据源和空权限回退。
- 模拟主链路覆盖成功查询、校验失败后回修、禁问词前置阻断、检索降级和 LLM 故障隔离。
- 使用当前配置模型进行四个真实问题验证，只记录 SQL 和行数，不输出查询数据内容。

## 当前明确边界

- 带行级范围的智能问数暂不接受 `OR`、`UNION`、`INTERSECT` 或 `EXCEPT`。这是安全优先的保守限制；需要此类统计时应改写为条件聚合或分别查询。
- 自动化与样本问句不能证明任意自然语言都能生成正确 SQL；置信度、结果解释和人工复核仍然必要。
- 数据库账号仍必须保持最小权限和只读配置，应用校验不能替代数据库、网络与部署层防护。
- 外部模型、检索服务和网络故障仍会使当次问数失败，但不应影响首页、课程、作业、通知、考勤、答疑或学生支持功能。
