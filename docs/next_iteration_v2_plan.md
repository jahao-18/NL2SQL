# 下一版迭代开发方案：角色工作台与真实教学协作

## 1. 版本定位

下一版暂定为 **V2：角色工作台版**。目标不是继续堆叠数据页面，而是让每个账号登录后都能看到与本人职责一致的待办、课程和操作入口，并能完成一段真实业务流程。

本版本解决四个当前问题：

1. 业务用户菜单中混入权限矩阵、账号列表、召回调试等平台开发功能。
2. 所有角色共用一套校级数据总览，权限过滤后留下大量空模块。
3. 教师、学生、辅导员之外的角色缺少可操作业务，页面更像数据演示而非高校产品。
4. 已有作业、学习支持、课程分析彼此独立，缺少通知、课程空间、考勤和答疑将它们连接起来。

## 2. 产品原则

### 2.1 首页回答“我今天要做什么”

首页优先展示本人今日课程、临期待办、未处理消息和异常事项，而不是先展示全校统计。统计只能作为辅助信息，不能取代业务操作。

### 2.2 角色不同，菜单和数据范围都不同

菜单由后端按角色返回，前端不能仅靠隐藏按钮实现权限。每个接口仍需进行课程成员、任课关系、行政班或学院范围校验。

### 2.3 不展示没有业务意义的空框

- 数据数组为空时，整个图表或表格模块不渲染。
- “待批阅 0”“未读通知 0”等具有完成意义的状态数字可以保留。
- 页面所有可选模块都没有数据时，只显示一个紧凑的当前状态和常用操作，不生成多个“暂无数据”卡片。
- 演示账号必须拥有与其角色匹配的确定性数据，不能依赖随机大库碰巧产生内容。

### 2.4 智能问数嵌入业务，不独占产品中心

保留智能问数，但问题模板和数据范围来自当前课程、行政班或学院页面。教师在课程页面问课程，学生问本人任务，辅导员问所带班级汇总，不能退回一套全角色共用的万能查询页。

## 3. 页面去留决策

| 当前页面 | V2 决策 | 原因与处理方式 |
| --- | --- | --- |
| 权限矩阵 | 从产品中删除 | 普通用户不需要查看表级权限；权限策略继续保留在后端代码和自动化测试中，不作为业务页面 |
| 账号管理 | 删除账号列表页 | 不再向任何普通角色返回全部演示账号；替换为只显示本人的“个人中心/账号安全” |
| 召回调试 | 从导航和生产页面删除 | 调试能力仅在开发模式保留接口或日志，不面向高校用户 |
| 数据总览 | 重构为角色首页 | 不再使用一套校级固定看板；按角色加载不同模块并动态省略空模块 |
| 智能问数 | 保留但降级为辅助能力 | 公共入口可保留，重点迁入课程、班级、学院上下文 |
| 数据维护、Schema、知识库、质量治理 | 移入“平台运维后台” | 仅平台管理员可见，与教学业务导航分组隔离 |
| 课程作业 | 保留并并入课程空间 | 作业是课程空间内的一种教学活动，同时保留教师待批和学生待办快捷入口 |
| 课程分析 | 保留 | 继续作为教师课程管理和学生个人学习的分析页 |
| 学习支持 | 保留并强化 | 只对辅导员和学生本人开放；教师仅看到课程事实汇总 |

此外，登录页当前展示全部演示账号及密码的做法只允许在显式 `DEMO_MODE` 下存在；正常模式只显示用户名、密码和忘记密码入口。

## 4. V2 信息架构

### 4.1 公共区域

所有角色都拥有：

- 角色首页
- 通知中心
- 个人中心：本人资料摘要、修改密码、登录状态
- 与本人权限匹配的智能助手

### 4.2 学生

菜单：`我的首页 / 我的课程 / 作业与任务 / 成绩与考勤 / 学习支持 / 通知中心`

首页模块：

- 今日课程与上课地点
- 最近截止的作业和被退回任务
- 未读课程通知
- 本人最新已发布成绩
- 本人可见的学习支持建议或预约回复

新增业务功能：

1. **我的课程空间：** 课程首页、教师公告、资料下载、作业、答疑。
2. **成绩与考勤：** 只显示本人成绩、成绩是否发布、每门课程考勤明细和请假状态。
3. **课程答疑：** 学生向当前课程提问，可选择公开给课程成员或仅教师可见；教师回复后通知学生。
4. **通知中心：** 作业发布、临期、退回、成绩发布、公告、答疑回复、辅导员预约回复。

明确不提供：其他学生名单、其他学生提交、教师内部统计、辅导员内部记录。

### 4.3 任课教师

菜单：`教学首页 / 我的课程 / 作业批阅 / 考勤管理 / 课程答疑 / 课程分析 / 通知中心`

首页模块：

- 今日授课安排
- 待批阅提交和待发布成绩
- 未回答课程问题
- 即将截止的作业
- 本人课程近期未交、迟交和缺勤汇总

新增业务功能：

1. **课程空间管理：** 发布课程公告、上传课程资料、维护资料可见时间。
2. **考勤管理：** 按真实课程场次发起点名，登记出勤、迟到、请假、缺勤，并允许教师在留痕后修正。
3. **课程答疑：** 查看本课程问题、回复、关闭或置顶高频问题。
4. **成绩册：** 将作业批阅结果汇总到课程成绩册；只支持草稿、待发布、已发布状态，不直接篡改学生最终总评。
5. **批量提醒：** 教师可对“本次作业未交”发送课程提醒，但看不到辅导员联系记录。

### 4.4 辅导员

菜单：`工作首页 / 所带班级 / 学习支持事项 / 学生预约 / 跟进日程 / 通知中心`

首页模块：

- 今日应跟进事项
- 逾期未复查事项
- 新增学生预约
- 所带班级近期未交、迟交和缺勤趋势
- 最近联系记录

新增业务功能：

1. **所带班级：** 查看行政班基本情况和必要的学生学习事实，不显示课程作业正文或教师评语。
2. **跟进日程：** 按 `follow_up_at` 形成日历/列表，支持到期、逾期、已完成。
3. **学生预约：** 受理、改期、完成或拒绝，操作后通知本人。
4. **支持事项合并：** 同一学生、同一课程、相近原因的重复事项提示合并，避免机械地产生多条待办。

### 4.5 教务处老师

菜单：`教务首页 / 教学任务 / 开课与排课 / 成绩提交 / 教学异常 / 教学分析 / 通知中心`

首页模块：

- 本学期待处理教学任务
- 未安排教师或教室的开课班
- 选课超容量/低于开班人数事项
- 超期未提交成绩的课程
- 待确认教学异常

新增业务功能：

1. **教学任务台账：** 课程、开课班、任课教师、容量、教室和学期状态。
2. **开课与排课检查：** 首版不实现复杂自动排课，只检查教师、教室、时间和容量是否缺失或冲突。
3. **成绩提交管理：** 查看课程成绩提交状态、退回原因、发布状态；不默认查看学生作业正文。
4. **教学异常：** 将未排教师、未排教室、容量异常、成绩逾期等转换为可处理事项，而不是只画统计图。

### 4.6 学院负责人

菜单：`学院首页 / 课程运行 / 教师工作量 / 教学质量 / 待办审批 / 通知中心`

首页模块：

- 本学院开课与选课概况
- 课程运行异常数量
- 教师工作量分布
- 成绩提交进度
- 课程质量趋势和聚合评教主题

新增业务功能：

1. **课程运行：** 只查看本学院开课班汇总和异常，不跨学院。
2. **教师工作量：** 展示班级数、学生人次和课程任务，不公开教师私密标识。
3. **教学质量：** 使用聚合成绩、通过率和脱敏评教主题；样本量过小时不展示排名。
4. **审批待办：** 首版支持课程开设调整或成绩提交退回两种确定性流程，避免做一个没有操作的领导看板。

### 4.7 平台管理员

菜单：`运维首页 / 数据源 / 数据质量 / 问数知识治理 / 审计日志 / 系统设置`

首页模块：

- 数据源健康状态
- 最近同步任务及失败任务
- 待处理质量问题
- NL2SQL 失败率和待审反馈
- 高风险越权拒绝审计摘要

管理员负责平台运行，不默认浏览学生提交、辅导员记录或全部账号明细。账号的创建、身份绑定和停用如果后续必须演示，应单独设计为组织账号同步流程，只展示必要字段、分页、范围授权和操作审计，不能恢复当前“所有账号平铺展示”的页面。

## 5. 角色首页的动态渲染规则

后端新增角色首页聚合接口：

`GET /api/workbench`

响应不再返回固定的十组数据，而是返回：

```json
{
  "role": "teacher",
  "summary": [],
  "sections": [
    {"type": "today_schedule", "title": "今日课程", "items": []},
    {"type": "pending_grading", "title": "待批阅", "items": []}
  ],
  "quick_actions": []
}
```

渲染规则：

1. `items` 为空且不是状态型模块时，后端不返回该 section。
2. 前端根据 `type` 选择对应组件，不预先在 HTML 中摆放所有卡片。
3. 表格没有行时不显示表头、边框和空白容器。
4. 筛选后无结果只在当前业务列表内部显示一条紧凑提示，不影响其他模块。
5. 每个角色至少有一个真实待办模块和一个快捷操作，保证首页始终可操作。

旧 `/api/teaching/dashboard` 暂时保留给管理员分析页，业务角色首页不再调用它。

## 6. 新增数据模型

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| `course_session` | 真实上课场次 | 开课班、日期、节次、教室、状态 |
| `course_announcement` | 课程公告 | 开课班、发布人、标题、正文、发布时间、状态 |
| `announcement_receipt` | 公告送达/已读 | 公告、接收用户、送达时间、已读时间 |
| `course_resource` | 课程资料 | 开课班、标题、文件元数据、可见时间、发布人 |
| `course_question` | 课程答疑 | 开课班、提问学生、问题、可见范围、状态 |
| `course_question_reply` | 答疑回复 | 问题、回复人、内容、时间 |
| `teaching_issue` | 教务异常待办 | 类型、课程/开课班、证据、负责人、状态、截止时间 |
| `grade_submission` | 课程成绩提交状态 | 开课班、提交人、版本、状态、退回原因、发布时间 |

已有 `notification` 表继续使用，但补齐列表、未读数、标记已读和按资源跳转接口。已有 `attendance` 表改为关联 `course_session`，不能再只依赖一个没有实际课次含义的 `session_no`。

## 7. 核心状态流程

### 7.1 通知与公告

`draft -> published -> withdrawn`

公告发布时按开课班选课关系生成接收记录；学生可标记已读，教师只能看到送达/已读汇总。

### 7.2 课程答疑

`open -> answered -> closed`，学生追问可使 `answered -> open`。

### 7.3 教学异常

`open -> assigned -> processing -> resolved`，关闭必须填写处理说明。

### 7.4 成绩提交

`draft -> submitted -> returned/approved -> published`。

学生只在 `published` 后看到成绩；学院负责人和教务处处理提交状态，不浏览作业附件。

## 8. 开发阶段

### 阶段 A：导航与隐私收敛

- 删除权限矩阵、账号列表、召回调试页面及普通用户入口。
- 增加个人中心；登录页普通模式不再公开演示账号。
- 技术治理页面全部限制为平台管理员。
- 实现后端菜单清单，拒绝仅靠前端隐藏。

验收：学生、教师、辅导员看不到任何账号列表、表权限或调试入口；直接请求对应管理接口返回 403。

### 阶段 B：角色首页与空模块治理

- 实现 `/api/workbench`。
- 将旧数据总览替换为六类角色首页。
- 建立 section 动态渲染机制，删除全部无数据空框。
- 补齐每个演示账号的确定性首页数据。

验收：六种角色首页内容不同；任何页面不存在连续多个空模块；跨学院、跨课程、跨行政班数据均不出现。

### 阶段 C：通知中心与课程空间

- 完成通知未读数、列表、已读和资源跳转。
- 实现课程公告、送达情况和课程资料。
- 将作业、课程分析、公告和资料整合到课程空间。

验收：教师发布公告或作业后，本课程学生收到通知，其他课程学生不收到；资料权限与课程成员关系一致。

### 阶段 D：考勤与课程答疑

- 建立课程场次。
- 教师按场次登记并修正考勤，学生查看本人记录。
- 实现课程答疑、教师回复和通知。
- 考勤事实继续为辅导员学习支持提供透明依据。

验收：教师不能登记其他教师课程；学生不能查看他人考勤或私密问题；辅导员只看到所带学生必要事实。

### 阶段 E：教务与学院工作台

- 实现教学任务台账和确定性教学异常。
- 实现成绩提交状态流程。
- 实现学院课程运行、工作量和质量聚合。
- 将学院/教务智能问数限制到对应汇总分析视图。

验收：教务处有可处理事项，学院负责人有本学院审批与聚合分析；两个角色不再只是查看相同校级图表。

### 阶段 F：产品回归与演示数据

- 按六种角色建立菜单、接口和字段权限测试。
- 使用独立临时数据库运行测试，禁止继续污染共享演示库。
- 准备教师发布公告与点名、学生提交与提问、辅导员跟进、教务处理异常、学院审批的演示脚本。
- 检查所有空态、错误态、无权态、移动端布局和通知跳转。

## 9. 本轮优先级

### P0：必须完成

- 删除三个不合适页面及相关普通用户入口。
- 角色首页和动态空模块。
- 个人中心与登录页隐私调整。
- 通知中心。
- 教师/学生课程公告、资料和课程空间。

### P1：形成产品差异

- 课程场次与考勤。
- 课程答疑。
- 辅导员跟进日程。
- 教务异常待办和学院审批。

### P2：后续增强

- 复杂排课算法、在线考试、自动组卷、毕业审核、转专业等重型教务功能。
- 企业微信、短信或邮件通知。
- 正式统一身份认证和组织目录同步。

P2 功能不应在本轮做半成品入口。

## 10. 版本完成标准

1. 六类角色都有不同且可操作的首页和导航。
2. 普通角色无法看到权限矩阵、账号列表、召回调试和平台数据治理功能。
3. 学生、教师、辅导员、学院、教务、管理员之间的接口范围均有自动化越权测试。
4. 页面不渲染无数据图表、空表格外框或无意义指标。
5. 教师到学生至少走通“公告/资料/作业/答疑/通知”中的三条完整链路。
6. 辅导员至少走通一次预约或学习支持复查。
7. 教务和学院至少各完成一种待办处理，而非只查看统计。
8. 智能问数故障不影响首页、通知、课程空间、作业、考勤和支持流程。
