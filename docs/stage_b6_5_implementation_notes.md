# B.6-5 迁移与完整回归实施记录

> 完成日期：2026-07-17

## 完成内容

### 一次性账号迁移

- 新增迁移标记 `b6_identity_position_authorization_v1`。
- 首次运行时把已有有效账号转换到 `user_role_binding` 和 `role_scope_binding`。
- 已有学院负责人兼任身份审核员时，自动补齐独立的审核员任职和角色绑定。
- 迁移完成后再次启动只同步权威教师/辅导员目录，不再依据 `app_user.role` 生成授权，也不恢复已撤销的岗位。

### 唯一权限事实源

- 数据库账号查询不再向认证逻辑返回旧角色和旧范围字段。
- 当前工作身份必须来自有效且未过期的角色绑定。
- 岗位角色还必须对应有效且未过期的任职记录。
- 学生/教师/辅导员自然人范围从已核验 `person_identity` 和统一 `staff` 身份获取；业务管理范围从 `role_scope_binding` 获取。
- 有效账号没有有效绑定时拒绝登录或签发业务令牌。
- 演示账号常量只用于显式演示模式下的登录页提示，不再作为认证兜底。

### 注册审核迁移

- 学生申请按辅导员的有效角色绑定和行政班范围寻找处理人。
- 教职工申请按学院负责人/身份审核员的有效角色绑定和学院范围寻找处理人。
- 教务或管理员兜底也要求存在有效绑定和有效岗位。
- 审核权限按当前令牌的绑定范围验证，不再读取审核员账号旧角色字段。

### 迁移完整性检查

新增 `identity_position_migration_report()`，检查：

- 有效账号是否缺少有效角色绑定。
- 有效岗位任职是否缺少角色绑定。
- 有效业务角色是否缺少必需范围。
- `admin`、`jwc`、`college` 泛化兼容账号是否占用正式组织岗位。

## 回归结果

新增 4 项 B.6-5 专项测试：

- 迁移完整性不变量。
- 15 个原有演示账号通过绑定模型继续登录。
- 篡改旧角色/范围字段不能改变权限。
- 只有旧角色字段而没有绑定的有效账号不能获得权限，重复迁移也不会为其补授权。

完整测试结果：

```text
103 passed, 2 warnings
```

两条警告分别来自 Starlette TestClient 兼容层和 `langchain-community` 的弃用提示，不是本阶段功能失败。
