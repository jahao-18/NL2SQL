## 1. 文档状态说明

本文使用以下状态，避免把可选能力或未来计划误写成现成功能：

- **已实现**：当前代码已有完整入口，满足对应权限和运行条件即可使用。
- **条件可用**：代码已经实现，但依赖 API Key、可选服务、外部数据集或特定配置。
- **仅后端**：已有后端接口，当前网页没有对应操作入口。
- **未实现**：当前不存在可用的完整产品流程，仅用于说明边界。

本文不记录任何真实或演示账号的明文密码。测试账号及实验身份信息只维护在不提交版本库的 `docs/demo_accounts_private.md` 中。

## 2. 项目定位与总体架构

本项目是面向高校教学管理场景的智能问数与教学业务平台。它不只提供自然语言转 SQL，还包含账号注册与组织权限、教学作业、课程分析、学生支持、知识治理和数据接入等完整业务工作台。

系统由以下部分组成：

- FastAPI 后端统一提供认证、权限、教学业务、NL2SQL、治理和数据维护接口。
- 原生 HTML、CSS、JavaScript 单页前端，根据后端返回的角色能力动态展示导航与页面。
- 默认教学演示库使用 SQLite，也支持配置 PostgreSQL 和其他 SQLAlchemy 可连接的数据源。
- Qwen/DashScope 用于数据源路由、查询扩展、SQL 生成、失败修复和结果裁判。
- 本地检索默认使用关键词/BM25、向量和关系图；可切换到 Elasticsearch、Milvus、PostgreSQL/pgvector 组成的服务端检索。
- JSON、JSONL、YAML 与 SQLite 共同保存画像、示例、反馈、治理项、审计和教学业务数据。

应用启动时会执行幂等数据迁移，补齐账号、组织、岗位、审核队列和教学工作流所需结构；可配置在后台预热检索索引。B.6 身份岗位迁移使用一次性迁移标记，首次完成旧账号转换后不会在后续启动中依据旧角色字段重新授权，也不会把已经撤销的正式岗位重新初始化。教师和辅导员权威目录仍会安全地增量投影到统一职工目录。前端静态站点挂载在根路径，API 统一位于 `/api`。

## 3. 用户、身份与权限体系

### 3.1 当前角色

| 角色 | 主要工作入口 | 数据范围与关键限制 |
|---|---|---|
| 学生 `student` | 我的首页、智能问数、我的课程、作业、课程分析、本人考勤、课程答疑、通知、学生支持、个人中心 | 仅本人数据；不能读取教师/学生名单、他人考勤、私密问题及全校汇总 |
| 教师 `teacher` | 教师首页、我的课程、作业管理、考勤管理、课程答疑、成绩提交、课程分析、个人中心 | 仅本人授课班级；限制学生身份字段、原始评教和全校数据 |
| 辅导员 `counselor` | 辅导员首页、智能问数、学生支持、审批中心、个人中心 | 仅被分配的行政班；可读取所带学生必要考勤事实但不读取教师备注、课程名单或答疑正文 |
| 学院负责人 `college_manager` | 学院首页、教学运行、成绩审批、汇总问数、审批中心、组织管理、个人中心 | 仅所负责学院；问数仅开放课程运行、工作量和质量汇总表 |
| 教务人员 `academic_office` | 教务首页、教学任务、教学异常、成绩发布、汇总问数、组织管理、个人中心 | 全校教学管理范围；问数仅开放教学运行汇总表，不浏览作业正文 |
| 身份审核员 `identity_reviewer` | 审批中心、个人中心 | 仅授权学院或队列中的注册申请 |
| 平台管理员 `admin` | 管理首页、智能问数、知识库、治理、数据接入、审批、组织管理、个人中心 | 平台配置与高风险管理能力；操作写入审计 |
| 普通职工 `staff` | 个人中心 | 已核验职工身份，但尚未取得具体业务岗位 |
| 个人自助 `self_service` | 个人中心 | 隐藏基础身份；仅在没有可用业务身份时进入，不包含教学或管理数据权限 |
| 待审核用户 `pending` | 注册进度 | 尚无业务数据访问权 |

权限不是单一角色字符串。系统把“人员身份、在岗任职、角色绑定、数据作用域、当前登录工作身份”拆开保存，因此同一个人可以同时担任教师和辅导员，也可以在多个合法身份之间切换。

`app_user.role` 仅作为历史兼容字段保留，不再用于运行时授权、默认身份排序、数据范围兜底或注册审核人选择。运行时权限的唯一事实源是账号状态、已核验人员身份、当前有效的 `user_role_binding`、对应 `role_scope_binding` 以及仍在有效期内的岗位任职。

### 3.2 登录、注册与账号生命周期

已实现能力：

- 使用学号或工号作为登录标识，不要求额外记忆一套业务账号。
- 学生和职工可在登录页自助注册，填写官方姓名、学号或工号及密码。
- 注册信息必须与知识库/教学库中的已有人员身份匹配；注册者不能自行选择管理员、学院负责人等高权限角色。
- 学生申请进入所属班级/学院审核队列；职工申请进入其组织范围内的审核队列。
- 待审核用户可以查询自己的申请状态。
- 审核员可以按条件查看申请，逐条通过/驳回，也可以勾选后批量通过或批量驳回。
- 审核通过后建立人员身份绑定和基础角色；学生获得学生身份，普通职工先获得职工身份，教师基础身份可获得教师角色。
- 防止同一学号/工号重复注册、身份被重复占用或申请重复提交。
- 登录返回服务端生成的导航、功能和数据范围，前端不自行推断权限。
- 一个用户有多个有效任职时，登录后可选择工作身份，也可以在系统内切换身份。
- 切换身份会签发新会话并使旧令牌失效，避免旧权限继续使用。
- 用户可在响应式个人中心查看当前账号、已核验状态、岗位身份和数据范围，并在独立的账号安全卡片中修改密码；修改后撤销既有会话。
- 连续登录失败达到 5 次会锁定 15 分钟。
- 会话令牌包含签发时间、12 小时有效期、会话版本、当前角色绑定和签名校验。
- 已结束或到期的任职会自动使关联角色失效并撤销相关会话。
- 有效账号如果没有任何有效角色绑定，会被拒绝进入业务系统；修改旧账号表中的角色或范围字段不能产生权限。

### 3.3 尚未实现的账号边界

- 没有完整的“忘记密码—短信/邮件验证—重置密码”自助流程。数据库中的重置申请结构不等于产品功能已完成。
- 没有短信、邮件、企业微信或统一身份认证平台的真实集成。
- 没有开放注册高权限岗位；管理员、教务人员、学院负责人、辅导员和审核员必须通过组织岗位任命获得权限。
- 当前认证适合项目演示和内部验证，生产部署仍需 HTTPS、密钥托管、密码策略强化、集中审计和安全评审。

### 3.4 生命周期基础、影响预览与账号安全冻结

B.7-0 已实现账号、人员身份、校内关系和岗位退出的只读基础能力：

- 为每个已核验自然人建立 `person_affiliation` 学籍/任职关系基线。
- 建立生命周期事件、账号状态历史、责任交接和销户申请数据结构。
- 为已核验人员建立隐藏的 `self_service` 基础绑定，只包含个人中心权限，不包含教学或管理数据。
- 正常存在业务身份时，`self_service` 不出现在身份选择列表；所有业务绑定暂停后才作为最低权限入口。
- 提供本人生命周期详情、管理范围内人员详情和事件影响预览。
- 影响计算覆盖角色、范围、岗位、会话撤销要求、已领取审核任务、教学班、辅导员个案、学生选课/未交作业、最低岗位覆盖阻塞和交接要求。
- 学生、辅导员、学院负责人、身份审核员、教务人员和管理员按照本人、行政班或学院范围访问，不能跨范围查看人员生命周期。
- 除账号安全冻结/恢复外，B.7 生命周期接口仍为只读预览，响应明确返回 `execution_available = false`，不会真正执行休学、毕业、调岗、离职或销户。
- 平台管理员可在组织教职工目录对已核验账号执行安全冻结/恢复，均须填写依据并完成当前管理员密码二次验证。
- 冻结和恢复都会递增 `session_version` 并使旧令牌立即失效；冻结账号不能登录或签发新令牌。
- 冻结不删除人员、岗位或角色绑定，恢复只恢复账号状态，因此冻结期间已撤销、结束或到期的岗位不会被复活。
- 系统禁止冻结当前管理员自身，并确保冻结后仍至少保留两名正式平台管理员；成功、错误二验和保底拦截均留有审计记录。
- 教务处可在组织与岗位页面办理学生休学、复学、毕业、退学，并按筛选后的在读学生批量办理毕业；平台管理员不替代教务决定学籍事实。
- 休学暂停学生业务绑定、撤销旧会话并保留 `self_service` 最低权限；复学按当前学籍创建新的学生绑定，不重新启用历史绑定。
- 毕业/退学撤销学生业务绑定、归档账号并禁止重新登录，成绩、作业、考勤、选课和支持记录不删除；批量毕业先校验整批对象并以单事务执行。
- 职工跨学院调动、离职和退休使用演示阶段的“双具名管理员确认”流程：首位管理员发起并复验密码，另一位管理员确认执行。
- 调动关闭旧学院关系、旧岗位和旧范围，建立新学院关系但不自动授予新岗位；离职/退休撤销业务角色、归档账号并使旧会话失效。
- 已领取审核任务返回原组织队列；教学班和未关闭辅导个案写入责任交接异常清单，保留业务历史并等待教务或学院明确接任。

### 3.5 通知中心与课程空间（阶段 C）

- 通知中心提供当前账号的未读数、加载/空/错误态、列表和已读标记；后端按资源类型返回安全业务页面目标，用户点击“查看详情”时先标记本人通知已读，再跳转到课程、作业、答疑、支持或教学运行页面。
- 任课教师可向本人授课班发布或删除课程公告；系统只为该班已选课且账号正常的学生生成送达记录与站内通知。删除采用软删除，公告及对应学生通知立即下线，但送达记录与操作审计继续保留。
- 学生只能读取本人选课课程空间中的已发布公告和在可见时间内的资料；教师只能维护本人任课班的公告、资料和公告送达汇总。
- 课程空间后端聚合课程基本信息、公告与资料；作业和课程分析仍复用既有受课程成员关系约束的接口。
- 教师和学生导航已接入“我的课程”与“通知中心”：教师可在课程空间发布公告，上传不超过 20MB 的受控格式附件或登记 HTTP(S) 外部资料链接；课程成员可按权限下载真实附件，学生可查看课程内容和标记通知已读。附件使用随机存储键保存，下载时再次校验课程成员关系，不暴露服务器文件路径。
- “我的课程”采用独立的响应式课程工作台：顶部切换当前课程，侧栏展示课程概览和业务入口，主区分别呈现公告时间线与资料卡片，教师发布公告和资料使用分离的编辑卡片；窄屏下自动切换为单列布局。

### 3.6 课程场次、考勤与答疑（阶段 D）

- 任课教师可以为本人课程建立真实课程场次，记录日期、时间、教室和主题；旧考勤数据在幂等迁移中关联到对应场次，不再只依赖抽象课次编号。
- 教师按场次获取实际选课名单，批量登记出勤、迟到、请假或缺勤；再次保存属于带审计记录的修正，场次同步进入已完成状态。
- 学生只能查看本人各课程场次及本人考勤状态和教师可见备注，不能读取同班名单或其他学生考勤。
- 辅导员只能通过本人负责行政班关系查看所带学生的课程、课次、日期和考勤状态，不返回教师考勤备注或课程名单；这些事实继续供规则化学习支持使用。
- 学生可在本人课程发起公开或私密问题。公开问题对课程成员可见但学生端隐藏提问者身份字段；私密问题只对本人和任课教师可见。
- 教师可回复、关闭、重新打开和置顶本人课程问题；学生可对本人未关闭问题追问，状态按 `open -> answered -> closed` 流转，追问使 `answered -> open`。
- 新问题通知任课教师，教师回复通知提问学生；答疑和通知不依赖智能问数服务。

### 3.7 教务与学院工作台（阶段 E）

- 教学任务台账展示课程、学院、教师、学年学期、教室、容量、选课人数和成绩提交状态；台账与成绩提交列表均可收起/展开，并使用内部滚动避免页面过长。两类列表均支持课程/教师关键词搜索，以及按权限范围动态提供的学年、学院下拉选项，可与学期、成绩状态组合筛选、一键重置并显示结果数。教师仅看本人授课班，学院仅看本学院，教务查看全校管理范围。
- 教务可按确定性规则刷新未排教室、超容量和低选课教学异常；教务或所属学院可标记处理中或填写说明解决，跨学院处理被拒绝。
- 成绩状态按 `not_submitted -> submitted -> approved/returned -> published` 流转：教师提交，学院或教务审批/退回，教务发布；退回必须填写原因，状态变化通知教师。
- 学院工作台聚合本学院课程运行、教师班级数/学生人次和课程质量；成绩样本少于 5 时不展示均分和通过率排名。
- 教务智能问数只开放 `academic_teaching_operations_summary`；学院智能问数只开放本学院教学运行、教师工作量和质量汇总表，并继续强制 `college_id` 行级条件。

## 4. 组织、岗位与审核队列

### 4.1 组织模型

已实现学校、教务处、学院、班级等组织单元，并维护职工目录、行政班、岗位槽位、岗位任职、角色绑定、数据作用域、审核队列和审核任务。

演示数据包含多个学院。学院负责人不是全系统共用的单一 `college` 账号：每个学院可以拥有独立的负责人岗位和人员，权限自动限制在该学院。

### 4.2 岗位任职全生命周期

组织管理页面及接口支持：

- 按组织单元、岗位类型和状态查看岗位槽位、当前任职人及缺岗/多人占岗等覆盖问题。
- 搜索职工并创建正式、临时或代理任职。
- 为辅导员选择一个或多个负责行政班，形成班级级数据范围。
- 更新任职范围、任职类型和有效期。
- 对现有任职续期。
- 在结束任职前预览影响，包括将失去的角色、范围、队列和会话。
- 结束任职并同步撤销角色绑定、范围权限和会话。
- 原子化转任：在同一操作内结束原任职并创建接任关系，减少权限空档或重叠。
- 临时/代理任职必须设置到期时间；到期后自动失效。
- 对新增管理员、敏感岗位变更、结束和转任要求当前管理员再次输入密码确认。
- 至少保留两名实名正式管理员，阻止导致管理员人数跌破下限的操作。
- 阻止管理员给自己授予、撤销或转移高权限岗位。
- 高风险操作写入审计记录。

### 4.3 审核队列

- 支持查看当前用户可管理的注册审核队列和队列任务。
- 队列按组织和职责分配，不依赖一个全校通用学院账号。
- 学院审核员只处理被授权学院的申请；管理员和相应管理岗位按角色规则访问。
- 审核中心支持条件筛选、全选、批量通过、批量驳回和单条处理。

## 5. 角色首页与教学数据看板

登录后首先进入角色化工作台。后端返回当前角色可见的模块、摘要、快捷操作和业务状态；没有数据的普通区块可隐藏，重要状态区块会保留。

已实现角色首页：学生、教师、辅导员、教务人员、学院负责人和管理员。

教学看板支持：

- 按学期、学院、专业、课程类型等条件筛选。
- 展示学生规模、教师/课程/教学班、成绩、考勤、作业、评教、预警等汇总卡片或分布。
- 展示教师工作量、出勤情况、风险提示和可继续追问的快捷问题。
- 学生和教师数据自动收敛到本人/本人授课范围。
- 学院负责人自动限定本学院；教务和管理员按授权范围查看。

## 6. 智能问数（NL2SQL）

### 6.1 完整问数链路

一次问数会执行以下已实现流程：

1. 普通教学角色固定使用教学业务数据源；管理员可根据手动选择、当前上下文、提问和历史对话选择已配置的外部只读数据源。
2. 加载数据源结构、字段信息、样例值、枚举值、业务词表和已发布 Schema 画像。
3. 对大库/宽表执行 Schema linking，筛选相关表和列，并补齐连接所需桥接表。
4. 使用最近对话、业务词表、指标定义和 Few-shot 示例构造提示词。
5. 调用 Qwen 生成只读 SQL。
6. 校验 SQL 安全性、可访问表/字段和当前用户行级范围。
7. 以只读连接执行，并限制超时和最大返回行数。
8. 对可修复失败调用模型重写 SQL 后重试。
9. 返回表格、SQL、解释、数据源、检索轨迹和置信度任务信息。
10. 后台异步裁判召回质量及 SQL/结果匹配度；失败时可用规则分数兜底，不阻断查询结果。

### 6.2 多路检索与知识增强

- 本地模式支持关键词/BM25、向量相似度、关系图、业务词表和指标匹配。
- 查询扩展可从中文问题中提取实体、属性及英文列名别名。
- 多路结果使用带权 RRF 融合，按表聚合后限制表数和宽表列数。
- 关系图可补齐连接被选中表所需的桥接表。
- 小型 Schema 可跳过检索直接使用全量结构。
- 可缓存原子信息、索引和关系图，也可在启动后后台预热。
- **条件可用**：服务端检索可连接 Elasticsearch（含可选 IK 中文分词）、Milvus、PostgreSQL/pgvector；任一路不可用时相应检索器降级，不应导致主查询崩溃。

### 6.3 查询交互

智能问数页面支持：

- 普通教学角色固定使用 `teaching`；管理员可自动或手动选择已配置数据源。
- 保留浏览器内多轮对话历史并用于追问。
- 为每个数据源维护浏览器本地业务术语和指标表达式。
- 查看生成 SQL、结果表格、自然语言解释、检索/执行轨迹和置信度。
- 对结果提交有帮助/无帮助反馈。
- 低置信结果进入治理复核队列（受治理阈值和设置控制）。
- 将结果导出为 CSV，并对可能触发电子表格公式的单元格做转义保护。
- 对适合的数据生成简单图表。
- 查看查询历史与反馈状态。

### 6.4 SQL 安全与权限

- 只允许单条 `SELECT` 查询，禁止写入、DDL 和危险语句。
- 按角色白名单限制可访问表，按敏感字段策略限制输出列。
- 受限表禁止使用无法确认字段安全性的 `SELECT *`。
- 学生、教师、辅导员和学院角色的查询必须包含系统要求的行级范围条件。
- 行范围在每个 CTE/子查询块分别校验，范围等式必须作为独立顶层合取条件；范围查询保守禁止 `OR`、`UNION`、`INTERSECT` 和 `EXCEPT`，避免布尔或集合绕过。
- 敏感输出字段在外层查询、CTE 和子查询中统一检查，支持识别表别名、未限定列和带引号标识符。
- 禁止 SQL 注释、数据库文件读取/输出函数、延时函数和其他高风险只读副作用能力。
- 没有 `ask` 功能的身份不能读取数据源目录或调用问数；空表权限不会回退为全表。
- 执行器使用只读数据库连接，并限制查询时长及最大返回行数（默认 5 秒、200 行，可配置）。
- 问题中的越权意图、受保护资源和字段别名也会参与拦截，但数据库和部署层仍需保留纵深防护。

## 7. 作业全流程

### 7.1 教师侧

- 查看本人授课班级及班级详情。
- 创建作业草稿，设置标题、说明、截止时间等内容。
- 修改草稿并发布给教学班。
- 查看作业提交名单和每位学生的提交状态。
- 查看提交详情、历史版本和附件。
- 将提交退回修改并填写说明。
- 录入成绩和评语；未发布成绩对学生不可见。
- 批量发布该作业的已评分成绩。

### 7.2 学生侧

- 查看与本人选课对应的作业列表和作业详情。
- 提交文本内容和/或文件附件。
- 在规则允许时重新提交，系统保存版本历史和原附件。
- 查看教师退回原因并再次提交。
- 只有教师发布成绩后才能看到分数和评语。
- 只能下载本人提交版本的附件。

### 7.3 共同规则

- 教师只能管理本人实际授课班级，学生只能操作本人提交。
- 作业、提交、退回、评分、成绩发布均有状态校验。
- 关键动作写入教学审计并生成站内通知数据。
- 到期作业的状态由迁移/维护逻辑自动更新。

## 8. 课程分析

- 教师可按本人授课班级查看分析上下文；学生只看到本人课程上下文。
- 提供预计算的课程摘要和指标定义，降低重复分析开销。
- 支持模板化教学问题，也支持在权限范围内回退到 NL2SQL 分析。
- 保存分析查询日志、结果状态和错误信息。
- 展示个人分析历史。
- 用户可以对分析结果标记“有帮助/无帮助”。
- 分析刷新或失败与作业提交流程隔离，不会因为统计失败而破坏作业业务数据。

## 9. 学生支持与辅导员工作台

### 9.1 规则化支持个案

- 根据透明规则从考勤、作业等证据生成支持个案，例如连续/累计缺勤或多次未交作业。
- 辅导员只看到本人负责行政班的学生个案。
- 个案展示触发原因、证据、建议行动、跟进时间、联系人记录和学生反馈。
- 状态流转覆盖待处理、已联系、跟进中、已改善和已关闭等业务阶段。
- 可控制部分支持信息是否对学生可见，保护内部工作记录。
- 刷新个案、状态变化和跟进记录进入日志、通知和审计。

### 9.2 学生求助/预约

- 学生可以创建咨询或预约请求。
- 请求按班级关系路由到对应辅导员。
- 学生查看自己的请求，辅导员查看权限范围内的请求。
- 辅导员可以回复、安排和更新请求状态。
- 学生不能查看其他学生的个案、请求或辅导员内部信息。

## 10. 知识库、Schema 画像与质量治理

### 10.1 知识库与 Schema 控制台

- 查看已注册数据源、数据源概况、健康/质量信息、示例和反馈。
- 搜索、展开并查看表和字段结构。
- 编辑表业务名、表说明、字段业务名、字段说明、枚举、单位、语义类型、聚合方式和默认过滤条件。
- 标记字段启用状态、敏感状态和废弃状态。
- 维护表关系和业务指标定义。
- 自动合并数据源原始 Schema、业务词表和结构化画像。
- 生成画像质量报告。
- 保存画像、创建版本快照、发布版本和回滚到历史版本。
- 更新或删除允许操作的版本记录。

### 10.2 治理复核队列

- 由用户负反馈、低置信问数、画像发布以及字段/关系/指标变更形成治理项。
- 按数据源、状态和类型筛选治理项。
- 设置状态、优先级、负责人和处理说明。
- 接受治理项时可沉淀为 Few-shot 示例、字段画像、表关系、指标定义或画像发布。
- 可填写原因驳回治理项。
- 治理设置包括：发布是否必须复核、错误反馈是否自动入队、低置信阈值、发布说明是否必填、默认状态筛选和页面条数。
- 治理复核和设置页面仅管理员可用。

### 10.3 反馈与示例

- 保存问数正向/负向反馈并支持列表和删除。
- 保存、更新、列出和删除 Few-shot 问答/SQL 示例。
- 治理接受动作可自动写入示例或画像；删除相关反馈时会清理关联治理项。

## 11. 数据源接入与数据维护

管理员数据接入页支持：

- 查看 `data_sources.yaml` 中注册的数据源及其只读/可写状态。
- 使用数据库 URL 测试连接。
- 注册已有 SQLite 文件路径。
- 粘贴/导入 CSV 内容并生成受管理的 SQLite 数据源。
- 扫描数据源结构和表。
- 分页浏览表数据。
- 对明确标记为 `writable` 的 SQLite 数据源执行受控新增、修改和删除。
- 查看数据维护审计日志。
- 校验数据源名、表名、文件名和上传大小；默认上传上限为 20 MB，可配置。

**仅后端**：`POST /api/data-access/sources/db-file` 支持以 Base64 内容导入 SQLite 数据库文件，当前网页只展示 SQLite 路径注册和 CSV 两个接入标签。

数据维护不是任意 SQL 控制台：只有管理员、只有允许写入的数据源、只有受控的行级 CRUD 接口可以修改数据。

## 13. 数据模型与演示数据

## 17. 当前明确边界

以下内容不能描述为已经完成：

- 生产级短信/邮件验证、找回密码、统一身份认证和多因素认证。
- 面向真实学校主数据系统的自动人员同步和离职/转岗消息集成。
- 主动销户；当前账号安全冻结/恢复、学生休学/复学/毕业/退学及职工调岗/离职/退休已可执行。正式人事角色、权威人事主数据同步以及教学/个案接任人的完整分派仍待后续阶段完成。
- 审批消息的真实短信、邮件或企业消息推送；当前为站内数据和页面待办。
- 完整的移动端适配、无障碍合规和多浏览器自动化验收。
- 大规模并发、灾备、集中日志、监控告警、密钥管理和正式等保方案。
- 任意数据库写入；数据维护只开放管理员受控接口和显式可写 SQLite 源。
- 不存在于 `BIRD_DATABASE_ROOT` 的外部 BIRD 数据库。
- 未启动或未正确配置的 Elasticsearch、Milvus、pgvector 服务端检索能力。
- 不经过人工确认就自动把所有低置信结果写入知识库；是否入队和如何接受由治理规则控制。

## 18. 文档持续维护规则

- 新增、删除或修改页面、按钮、业务流程和状态机。
- 新增、删除或改变 API 的方法、路径、权限、参数语义和结果语义。
- 新增角色、岗位、导航、表/字段/行级权限或审核范围。
- 新增数据模型、外部依赖、配置项、脚本或部署方式。
- 将“仅后端”变为页面可用，或将“条件可用”改为默认可用。
- 修复导致原功能描述不再准确的重要缺陷。

每次更新至少完成以下检查：

1. 修改本文相关功能章节，而不只追加更新日志。
2. 同步 API 清单、角色矩阵、页面清单、配置或边界说明。
3. 更新顶部“最后核对日期”。
4. 在下方记录一条简短变更摘要。
5. 用当前后端路由和前端页面标识反查，确保没有漏项或把规划写成实现。
6. 若测试数量或质量结论发生变化，同步更新质量基线。
