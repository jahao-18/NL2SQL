# V3-1.2 服务端会话与消息完成报告

> 完成日期：2026-07-18
> 阶段状态：已完成
> 下一任务：V3-1.3 统一问题编排器

## 1. 数据迁移

新增 V3 migration `v3_0002_assistant_sessions`，当前 SQLite schema version 为 `3002`。迁移通过 V3-0.3 的同一事务机制创建：

| 表 | 用途 | 关键约束 |
|---|---|---|
| `assistant_session` | 助手会话 | 绑定 `user_id + role_binding_id`；页面枚举；软删除；客户端请求 ID 按当前身份唯一 |
| `assistant_turn` | 会话轮次 | 会话内序号唯一；状态和回答类型枚举；客户端请求 ID 按会话唯一 |
| `assistant_saved_query` | 收藏查询基础 | 绑定用户和角色；标题在当前身份内唯一；可关联会话和轮次 |

三张表均包含必要外键、唯一约束、查询索引、`created_at` 和 `updated_at`。迁移失败仍由 V3 执行器整体回滚。

## 2. 会话服务

新增 `app/core/assistant_sessions.py`，当前提供内部服务函数：

- 创建会话，保存 V3-1.1 验证后的上下文摘要。
- 分页列出当前用户当前工作身份的未删除会话。
- 分页读取会话轮次。
- 修改标题和收藏状态。
- 软删除会话，重复删除返回稳定的 `already_deleted` 状态。
- 追加问题轮次并更新会话最后问题和更新时间。
- 使用 `client_request_id` 保证重复创建和重复轮次请求不产生多条数据。

任何读取和写入都会重新验证账号状态、会话版本、角色绑定与岗位有效期。查询条件同时包含 `user_id` 和 `role_binding_id`；其他用户或同一用户的其他工作身份统一按不存在处理，不暴露会话是否真实存在。

## 3. 数据最小化

会话只保存：

- 标题、页面和验证后的上下文摘要。
- 最后一个问题的短文本。
- 收藏、删除和时间状态。

轮次只保存：

- 问题、回答类型、执行状态。
- 验证后的上下文摘要。
- 最大 1000 字符的 `safe_answer_summary`。
- 安全错误码和执行时间。

没有结果行、附件、完整回答正文或大结果集字段。安全摘要需要由后续编排器在写入前完成数据最小化。

2. 轮次分页、顺序和重复请求去重。
3. 跨用户及角色切换后的跨身份隔离。
4. 冻结账号不能继续读取。
5. 软删除可重复且删除后不能读取或追加轮次。
6. 三张表的时间字段、外键和索引检查。

## 5. 已知边界

- 尚未提供 `/api/assistant/sessions` 系列接口和前端入口。
- `assistant_saved_query` 当前只有数据结构，收藏查询服务在后续统一助手能力中实现。
- 动作草稿尚未建立，因此删除会话时暂时没有需要作废的动作草稿；建立动作草稿后必须补充级联失效逻辑和测试。
- 当前只保存终态轮次；流式输出、运行中状态恢复和任务队列不在本阶段范围。
