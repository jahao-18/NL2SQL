# 当前问数流程风险回归报告

## 结论

**风险回归已完成，但不建议把当前构建作为“成绩发布与问数完全打通”的验收版本。**

- 覆盖门禁：`PASS`
- 发布门禁：`FAIL`
- 自动化定向回归：`132/132 PASS`
- 真实 UI 主链：`PASS`
- 真实学生/教师/教务 API 主链：`PASS`
- 当前服务：健康检查 200，进程 61228，测试期间代码哈希未变化

发布门禁失败的原因是未解决 P1 关联缺陷 D-001：教务发布的新课程总评没有接入学生问数口径。

## 正常能力

1. 共享问数面板能正常加载并调用 `/api/assistant/query`。
2. 学生“我选了哪些课程？”返回数据库系统，范围限定为本人。
3. 教师“我负责哪些课程？”返回本人授课课程，SQL 带 `teacher_id = 900001`。
4. 教务成绩发布状态走确定性语义指标，返回 `published: 1`。
5. 学生未读通知走确定性指标并正常返回。
6. 服务端会话追问有效；客户端伪造历史、伪造页面上下文和越权范围有自动化保护。
7. 身份证号等敏感问题在模型与 SQL 执行前拒绝。
8. 模型/检索失败与总超时会结构化失败，不拖垮普通业务接口。
9. 旧 `/api/ask` 兼容接口回归通过。

## 未解决问题

### D-001（P1）已发布课程总评未接入问数

学生首页与数据库发布基准为数据库系统 `91.0 / 100.0`，但两种同义问法都生成旧 `score` 表查询并返回 0 行。

根因是学生 `personal_learning` 域只开放旧 `score`，新 `grade_submission` / `grade_submission_detail` 没有安全问数投影或确定性查询入口。

建议修复方向：不要直接向学生开放完整审批表；建立只包含“本人、已发布、当前冻结版本”的安全成绩视图或确定性语义指标，再让助手优先使用该口径。

### D-002（P2）本人课程教师问题被过度拒绝

课程页允许显示李老师，但“这门课是哪位老师教的？”和“数据库系统的任课教师是谁？”都被 `teacher_identity` 别名规则拒绝。

建议把“本人已选课程的任课教师姓名”与“全校教师身份/名单查询”分开授权。

### 既有观察

学生页面初始化仍会请求管理员数据源接口并得到一次 403（功能目录已登记 ZJH-012）。当前未造成问数面板错误或回答失败。
