# 阶段 A 实现记录：入口收敛与权限基线

## 1. 阶段目标

阶段 A 不新增孤立业务页面，先解决产品入口、账号隐私和前后端权限不一致的问题，为后续按角色扩展真实业务能力建立可靠基线。

## 2. 已完成内容

### 2.1 移除低价值入口

- 删除普通产品中的“权限矩阵”“账号管理”“召回调试”页面和侧边栏入口。
- 删除召回调试接口 `/api/debug/retrieval`。
- 业务域配置不再返回全量账号清单。
- 数据结构、语义配置、数据质量、示例问法和治理设置等技术能力仅管理员可访问。

### 2.2 建立后端角色导航

后端会根据当前登录身份返回 `navigation`，前端仅渲染服务端授权的菜单，不再依赖静态菜单隐藏。

| 角色 | 阶段 A 可见入口 |
| --- | --- |
| 平台管理员 | 数据总览、智能问数、数据接入、知识库、语义配置、质量治理、治理设置、个人中心 |
| 教务处 | 数据总览、智能问数、个人中心 |
| 学院负责人 | 数据总览、智能问数、个人中心 |
| 任课教师 | 数据总览、作业与批改、课程分析、智能问数、个人中心 |
| 辅导员 | 学生支持、智能问数、个人中心 |
| 学生 | 作业中心、课程分析、学生支持、智能问数、个人中心 |

该清单是阶段 A 的权限基线，后续阶段新增业务模块时应先在后端登记角色入口，再实现页面。

### 2.3 登录与个人信息隐私

- 登录页默认不展示演示账号和默认密码。
- 只有显式配置 `DEMO_MODE=true` 时，登录页才展示不含密码的演示账号。
- 新增 `/api/auth/me`，个人中心只展示当前用户的姓名、账号、角色和数据范围。
- 会话数据不再向浏览器暴露表名、禁用字段、禁用词和原始行级权限条件。
- 保留当前用户修改自己密码的能力，不提供全员账号浏览或代改入口。

### 2.4 接口权限收敛

以下接口现要求管理员身份：

- `/api/business-domains`
- `/api/schema`
- `/api/profile`
- `/api/profile/versions`
- `/api/quality`
- `/api/examples`
- 原有数据接入与治理设置接口

前端同时按特性判断是否请求这些接口，避免普通角色进入工作台后产生无意义的 403 请求。

### 2.5 测试环境隔离

- 测试会复制教学演示数据库到临时目录，作业提交附件也写入临时目录。
- 测试开始前仅在临时副本中清理历史验收产生的记录。
- 测试运行不再修改共享的 `data/teaching.db`，作业版本回归可以稳定重复执行。

## 3. 验收结果

- 自动化测试：`60 passed`。
- Python 编译检查通过。
- `app/static/app.js` 与 `app/static/api.js` 语法检查通过。
- 运行态登录配置返回 `demo_mode=false` 且不包含账号。
- 学生导航不含任何平台治理入口，直接访问 `/api/schema` 返回 403。
- 管理员导航保留平台治理入口。

## 4. 后续开发约束

1. 新页面必须对应真实角色任务，不以技术模块名称作为普通用户入口。
2. 页面权限必须同时具备后端授权、前端导航控制和接口越权测试。
3. 列表默认只返回当前角色业务范围内的数据，不提供无边界全量查询。
4. 无数据时使用角色任务、待办或明确空状态，不保留无意义空卡片。
5. 后续阶段不得重新在登录页或个人中心暴露全量账号、默认密码和内部权限规则。
