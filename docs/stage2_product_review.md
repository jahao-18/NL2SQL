# 阶段 0-2 产品审查与优化记录

## 1. 审查结论

阶段 2 已具备“发布作业 - 学生提交 - 教师退回/评分 - 成绩发布”的最小业务链路，但原实现更接近接口演示页，不能直接作为高校教学平台场景答辩。主要问题不是功能数量，而是课程上下文、角色工作台、数据完整性和真实文件处理没有形成产品闭环。

本轮按高校教学平台的基本组织方式，将页面调整为“身份工作空间 - 开课班 - 作业 - 学生名单/本人任务”的四级结构。教师与学生进入同一菜单后看到不同工作台，所有数据范围仍由服务端校验。

## 2. 已发现并修复的问题

| 优先级 | 原问题 | 现实影响 | 本轮处理 |
| --- | --- | --- | --- |
| P0 | 教师页面写死开课班 `900001` | 第二位教师仍会看到第一位教师的页面，产品逻辑失真 | 新增“我的开课班”接口，前端按当前教师动态选择课程 |
| P0 | 教师名单只查询已有提交记录 | 未交学生从页面消失，无法催交或形成完整统计 | 改为以选课花名册为主表，左连接提交记录，明确显示未提交 |
| P0 | 附件只保存文件名，没有文件内容 | “上传作业”实际上不可用 | 支持 5MB 内受控类型附件，随机对象键存储，下载再次校验学生/任课教师权限 |
| P0 | 每个请求重复执行迁移和演示数据播种 | 并发时数据库锁等待，并可能污染业务数据 | 迁移只在启动或显式初始化执行，业务连接不再修改结构和种子数据 |
| P0 | `closed` 状态仍允许提交 | 教师关闭作业后学生仍能覆盖提交 | 仅 `published` 状态允许提交；逾期是否接收由补交开关决定 |
| P1 | 截止时间按字符串和 UTC 直接比较 | 本地时间、时区和字符串格式会导致误判 | 服务端统一解析为上海时区并归一为 UTC，再进行时间比较 |
| P1 | 草稿能保存但不能修改 | 草稿一旦填错只能废弃，违背草稿含义 | 增加草稿编辑接口与页面回填，发布后禁止直接修改 |
| P1 | 辅导员出现“课程作业”菜单但页面不支持该角色 | 菜单与岗位职责不一致 | 辅导员移除作业功能入口，后续进入阶段 3 的学习支持工作台 |
| P1 | 教师默认进入泛化数据看板 | 核心日常工作入口不突出，还可能混入不适合教师的指标 | 教师和学生登录后默认进入课程作业；管理岗位仍进入分析看板 |
| P1 | 每条提交行都重复放“发布成绩” | 容易误解为发布单人成绩，操作层级错误 | 发布成绩提升到作业级操作，并显示本次待发布数量 |
| P1 | 学生提交后不回显附件，页面也不能主动修改提交 | 用户无法确认上传结果，只能等待教师退回后重交 | 返回最新提交版本、说明、附件和大小；未评分前允许保存新版本，新文件可替换附件，不选文件则保留原附件 |
| P1 | 教师默认按截止日期打开作业 | 刚收到的提交可能藏在其他作业中，形成“教师看不到”的体验 | 教师作业队列按最新待批提交优先，并在花名册直接显示说明、附件和版本数量 |
| P2 | 原页面同时铺开发布表单和所有提交表格 | 信息密度失控，缺少课程和作业上下文 | 改为课程选择器、作业主列表、批阅详情三段式工作台 |

## 3. 当前产品结构

### 学生工作台

- 只查询本人选课产生的作业，并按全部、待完成、已提交、已完成筛选。
- 展示课程、截止时间、要求、当前状态、退回意见和已发布成绩。
- 被退回后允许产生新版本；已进入批阅的版本不能被无条件覆盖。
- 上传文件保存在服务端受控目录，原文件名不参与存储路径拼接。

### 教师工作台

- 课程选择器只返回当前教师实际承担的开课班。
- 作业主列表展示提交进度、待批数量和未交数量。
- 作业详情使用完整选课花名册，教师可以明确看到未交学生。
- 草稿支持编辑和发布；提交支持退回或评分；未发布成绩在作业层统一发布。
- 教师只能下载本人开课班的学生附件，其他教师和其他课程学生会被拒绝。

## 4. 阶段 2 仍然存在的边界

以下内容没有伪装成已完成，应作为后续阶段的明确任务：

1. 站内通知已有数据表和写入逻辑，但尚无通知中心、已读状态和截止提醒调度器。
2. 作业发布后暂不支持教师变更截止时间、关闭、归档或删除；这些操作需要补充变更通知和审计规则后再开放。
3. 当前使用 SQLite 与本地附件目录，适合课程项目和单机答辩；多人部署应切换 PostgreSQL 与 MinIO/S3，并增加病毒扫描。
4. 尚未实现教师批量评分、评分量规、查重、在线预览和课程资源关联，这些属于作业系统的增强能力，不应挤占阶段 3 的辅导员闭环。
5. 已写入的通知尚未从 UI 呈现，因此答辩时只能演示业务状态流转，不能宣称通知中心已完成。
6. 原有 NL2SQL 分析入口仍需在阶段 4 验证行级范围是否覆盖所有自由问句；业务 API 权限通过不等于自然语言查询天然安全。

## 5. 后续开发顺序

1. 先完成本阶段回归：教师课程范围、完整花名册、草稿发布、附件权限、成绩可见性和重复提交。
2. 进入阶段 3，单独建设辅导员“学习支持待办”，不复用教师作业页面，不展示教师评语和学生附件正文。
3. 补通知中心和提醒任务，让作业发布、退回、成绩发布在学生端有统一入口。
4. 阶段 4 再把提交率、迟交率、待批量等固定口径接入 NL2SQL，且只查询脱敏分析视图。
